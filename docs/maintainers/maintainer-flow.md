# Maintainer flow and recovery

Use the current protected-base implementations. `npm run merge:batch -- --prs <PR_LIST> --prepare-only --reviewed-head <FULL_HEAD_SHA>` inspects each selected PR and approves only its allowed exact-head workflows without waiting or merging. Supply one exact-head attestation per changed skill/web-source head. A normal batch performs this preparation first, then recomputes policy, evidence, tuple and branch protection before each ordered merge. Early workflow approval never authorizes a later merge; head or base drift still requires a fresh invocation and review. If an earlier merge changes evaluator code, workflow policy, package dependencies or maintainer instructions, stop and restart from the refreshed protected base rather than using modules already loaded from the previous base.

Multi-PR merges record a one-hour `aas-maintainer-batch` deployment lease before the first merge. Only repository-owner-created, schema-valid leases can defer canonical generation. Main CI and repo hygiene check current-main identity and active leases before expensive generation, then check again before publication. A completed or failed batch closes its own lease and dispatches protected-main CI; manual main dispatch can publish canonical drift through the same protected PR lane. A failed dispatch restores a recoverable lease. `.github/workflows/maintainer-batch-recovery.yml` checks twice per hour and dispatches convergence after lease expiry. GitHub schedules are best effort, so manual recovery remains available. Lease expiry stops further batch merges; it never extends review authority, weakens strict checks or guarantees wall-clock savings. Concurrent batches fail closed on competing leases.

`skills/<skill-id>/LICENSE` is ordinary reviewed skill support only when it is a regular non-executable UTF-8 file, nonempty, free of binary/control bytes and at most 64 KiB. Both old and new changed blobs are checked. This does not authorize scripts, infer license compatibility, or remove semantic/provenance review. Other reviewed bundle exceptions still use the protected-base ledger. Use `npm run maintainer:dossier -- --prs <PR_LIST> --output <ABSOLUTE_JSON_PATH>` to collect exact heads, complete skill trees, blob identities and policy findings for one batch; the dossier never edits the exception ledger or declares content reviewed.

README Official Sources and Community Contributors are generated by `sync:source-credits` during `sync:repo-state`, using canonical frontmatter and `data/source-credits.json`. The editorial ledger preserves the complete pre-migration credit text, including sources without complete metadata; never replace it with an index-only reconstruction. Add custom wording or historical corrections to that ledger, and fix wrong `source_repo`/`source_type` in the skill. Source PR checks preview attribution from immutable head metadata; ordinary new imports need no README edit. Verify resulting README attribution after the protected canonical PR merges. Keep Top Contributors and Repo Contributors under their existing generators.

`npm run pr:preflight -- --json` executes validation, conditional reference validation, docs security, immutable-head credit preview and the full test suite, collecting each exit status and output. Before tests it installs dependencies and regenerates the catalog/web preview in an isolated checkout of the requested immutable head, then removes that checkout; generated preview files never pollute the contributor worktree. This isolation is not a sandbox for unreviewed test scripts; inspect executable changes before testing another head. A failed preview is reported separately and leaves the test marked as skipped/blocked. `--no-run` emits classification only. Policy/fork enforcement remains explicit through its existing flags. Functional validation and semantic review remain separate; a passing preflight is not merge authority.

Before preparing a requested release, run `npm run release:plan -- --base <PREVIOUS_TAG> --head <CANDIDATE_SHA> --output <ABSOLUTE_JSON_PATH>`. It records full base/head SHAs, complete-tree skill additions/updates/removals, canonical count, PR numbers from merge subjects, Git-author candidates for thanks and commit evidence. Review attribution and editorial copy; imported PR authors and coauthors may differ from Git authors. Re-run with `--check <ABSOLUTE_JSON_PATH>` and the same base/current candidate to reject a stale plan.

After publication, run `npm run release:verify -- --version <X.Y.Z> --output <ABSOLUTE_JSON_PATH>`. Every invocation refreshes observations; old passed rows are never reused as authority. Before executing any tagged generator or MCP runtime, require a published immutable remote tag that matches the local tag and is an ancestor of verified protected main; failed provenance blocks execution while public observations remain available. It independently reports expected/observed identity, evidence and next action for clean local/remote main, remote tag/GitHub Release, npm/dist-tag, exact-commit CI/CodeQL/release-tag Pages, isolated canonical regeneration, live catalog/SEO, the complete legacy redirect set and existing default user/project Codex/Claude MCP hosts. Supply `--hosts <ABSOLUTE_JSON_PATH>` with a complete array of `{ "host": "codex|claude", "config": "/absolute/config" }` for custom host locations. It never modifies a real host config, publishes, or fixes remote state. Native hosts using a different Node runtime are reported for explicit verification rather than executed automatically.

Fresh stdio `initialize` and `tools/list` verify published bytes and catalog identity, but do not prove that an existing desktop session reloaded. Reconnect every inventoried configured client, discover and invoke AAS in that client, then explicitly attest the exact released SHA using `--client-confirmed-head <FULL_RELEASED_SHA>`. Until that attestation and every machine check pass, `release:verify` returns incomplete. Report excluded custom host locations and any credentials, permissions, CDN or client boundary truthfully. Saved JSON is a resumption checklist; it is never a publication authorization or cached completion proof.

## Validation and implementation scope

The source change includes negative regressions for binary/oversized/executable licenses, failed/missing/approval-wait CI, stale release plans, failed/latest wrong-SHA workflow observations, lease expiry, competing batches, failed dispatch recovery, preserved source attribution and missing native-client confirmation. Required CI continues to run the full unsharded test suite. Ordinary artifact preview checks out the standalone verifier shallowly; canonical reproduction retains history. This update does not publish a package or create/update any local MCP host.
